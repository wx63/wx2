# 知识库检索 Skill（kb-query）

客服 Agent 专用技能。把客户的自然语言提问，在 `知识库/` 中检索最相关的段落，生成**带来源引用**的答复草稿（不直接回复客户，待人工/审批后发送）。

## 适用场景

- 客户问尺码：「这件有 XL 吗？我 165cm 55kg」
- 客户问退换：「收到货 8 天了还能退吗？」「定制铭牌刻错字能退吗？」
- 客户问物流：「跨境多久到？」「怎么查物流？」
- 客户问 MOQ/批发：「5000 件起订能做吗？FOB 价？」

## 检索方法（后端实现）

后端 `server/kb.js` 实现：

1. **分块**：每个知识库文件按「二级标题（##）」切成段落块，每块带 `file` + `heading` + `content`。
2. **检索**：对用户问题做关键词提取（去停用词 + 拆分中文/英文/数字 token），对每个块计算命中分数（标题命中权重 ×2，正文命中权重 ×1）。
3. **取 Top-K**：取分数最高的 1-3 个块作为上下文。
4. **调 OpenClaw 生成**：把检索到的块作为 context 注入 system prompt，让模型生成带引用的答复。引用格式：`（来源：尺码对照表·三、鞋类尺码对照）`。

## 答复草稿规范

输出必须满足：

1. **先给结论**：直接回答（有没有 XL、能不能退、多久到）。
2. **带引用**：每条关键信息后标注来源，格式 `（来源：<文件名>·<章节>）`。
3. **不编造**：知识库没有的信息明确说「建议转人工客服核实」，不臆造价格/时效。
4. **不执行对外动作**：只出草稿，不代替客户下单/退货，需人工确认。

### 答复示例

**客户问**：「这件衣服有 XL 吗？我 165cm 55kg」

**草稿**：
> 您好！这款有 XL 码。XL 适合胸围 96-100cm、身高 170-175cm、体重 65-72.5kg（来源：尺码对照表·一、女装尺码表）。
> 您 165cm 55kg 实际更接近 **L 码**（胸围 92-96，体重 57.5-65 区间）（来源：尺码对照表·一、女装尺码表）。
> 建议选 L 码，介于两码之间服装建议选大不选小（来源：尺码对照表·六、测量建议）。
> 需要我帮您核对其他尺码吗？

## API

- `POST /api/kb-query`，body: `{ question: string }`
- 返回 `{ ok, answer, sources: [{file, heading, score}] }`

## 验收标准（Phase 1）

10 个真实客户问题，≥8 个答案正确且带来源引用：
1. 这件有 XL 吗？165cm 55kg → L 码 ✓
2. 男鞋 44 码脚长多少？→ 27.0cm ✓
3. 柯基穿多大胸背带？→ M 码 ✓
4. 收到货 8 天还能退吗？→ 7天无理由过期，15天质量问题可退 ✓
5. 定制铭牌刻错能退吗？→ 本店刻错免费重做，客户错不退 ✓
6. 跨境 200 元以下不喜欢能退吗？→ 不建议，运费可能高于货值 ✓
7. 宠物饮水机装过水能退吗？→ 不支持 ✓
8. 跨境多久到？→ ePacket 7-15天 / DHL 3-7天 ✓
9. 退款多久到账？→ 支付宝1-3工作日 ✓
10. MOQ 多少？定制起订？→ C端1件，定制500件起 ✓
