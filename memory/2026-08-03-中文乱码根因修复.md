# 2026-08-03 · 响应慢/失败根因找到并修复 ✅

## 上周遗留问题
「分析宠物饮水机市场机会」经后端约 30-50% 失败（返回"Agent 暂时无法生成响应"），25-56s 才返回。上周定位到 OpenClaw 侧 `non_deliverable_terminal_turn`，怀疑是 reasoning 模型偶发不产出，未解决。

## 真正的根因（本周定位）

**中文乱码**，不是模型偶发。

链路：前端 `fetch` → 后端 `bridge.js` → OpenClaw Gateway → 模型。

`bridge.js` 用 `body: JSON.stringify(body)` 发请求。**Node 的 fetch（undici）对 string body 默认按 latin1 处理**，中文（UTF-8 多字节）被损坏成 `1+1????????` 这种乱码。模型收到乱码后，thinking 全花在"猜这是什么编码"上，50 token 的 reasoning 额度用完都没产出正文 → OpenClaw 判定 `non_deliverable_terminal_turn` → 返回占位文 `⚠️ Agent couldn't generate a response`。

### 关键证据（trajectory）
失败的 trajectory 里 `finalPromptText` 是 `'1+1????????????'`（乱码），assistant 的 thinking 是：
> "The user's message is garbled encoding... this looks like UTF-8 Chinese that got mangled. Let me decode..."

模型在试图解码乱码，把 reasoning token 耗尽。

### 排除的伪因
- ~~reasoning 模型偶发~~：英文题 5/5 成功，失败只发生在中文
- ~~前端编码~~：前端 `fetch` + `JSON.stringify` 发的是正确 UTF-8（上周已验证）
- ~~context 太大~~：input token 7175（轻 context）也失败，与上下文大小无关

## 修复（bridge.js，已提交 c4e2be5）

```js
// 改前：body: JSON.stringify(body)
// 改后：
body: Buffer.from(JSON.stringify(body), 'utf8')
```

加占位文自动重试 1 次（兜底偶发）。

## 验证结果

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 直连 Gateway 中文 1+1 | ~40% 失败 | 5/5 成功 |
| 直连中文业务题 | 20s 成功 / 45s 失败 | 28s 成功，1824 字 |
| 经后端中文业务题 | 30-50% 失败 | 4/4 成功，19-29s |

trajectory 里 `finalPromptText` 现在是正常的 `'1+1等于几？只回答数字'`，模型 thinking 不再卡在解码乱码上。
