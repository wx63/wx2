## 技术决策与踩坑

- **流式执行用 async/await + setTimeout 串行**，每步 420-940ms，共 4-6 步。jsdom 测试需留足 5.5s 等待，否则只跑到一半步骤，误判失败。
- **审批条目 ID 用 `AP-00X`**，X 基于 `APPROVALS.length+1`。注意：unshift 新条目后 length 变化，但 ID 在 push 前算好，无冲突。
- **导出 CSV 加 BOM（`﻿`）**：Excel 直接双击打开中文不乱码。
- **路由规则用关键词数组 includes 匹配**，简单可靠；对外动作单独一套 ACTION_RULES，二者解耦（一条指令可能既路由到 Agent 又触发审批）。
- **jsdom 测试踩坑**：
  - `Object.defineProperty(window.location, "href", ...)` 会抛 `Cannot redefine property`，改用 `delete window.location; window.location = {...}` 替换整个对象
  - jsdom 不加载外部 `<script src>`，需手动 `createElement("script")` 注入 app.js 内容
  - `loadUser()` 无 oc_user 会 `location.href = "login.html"` 触发 jsdom 的 "Not implemented: navigation" 报错，测试前预置 oc_user 并屏蔽 location 即可
  - hot 线索数据里是 4 条不是 3 条，断言写错会误判
