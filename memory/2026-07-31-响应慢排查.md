# 2026-07-31 · 响应慢排查（未解决，下周继续）

## 现象
搜「分析宠物饮水机市场机会」半天不出结果（实测 105s 超时返回失败）。

## 已定位的根因（3 个，全在 OpenClaw 侧）

### 1. main agent 上下文巨大（3-5 万 token）
直连 Gateway 看 usage：prompt 高达 1.6w-7.5w tokens。来源是 main agent 自己加载的 `AGENTS.md/SOUL.md/IDENTITY.md` + workspace 上下文（里面有海报/视频/html 抓取文件等一堆东西）。每次请求都要处理这堆，简单题也吃 5-10s。

### 2. reasoning 默认全开 + 偶发 non_deliverable_terminal_turn
`deepseek-v4-flash` 的 `reasoning: true` 默认开，会先做一长串内部思考再输出。
- 加 `reasoning_effort:"low"`：简单题 5s→3s，但复杂题仍 20-45s。
- **偶发致命问题**：trajectory 显示 `terminalError: "non_deliverable_terminal_turn"`，model.completed 里 `assistantTexts: []`——模型有 reasoning（thinking）但没产出可交付正文，Gateway 就吐固定占位 `⚠️ Agent couldn't generate a response. Please try again.`。**这个偶发且无规律**：同样参数连测，1+1 三次里一次失败、市场分析有时 20s 成功有时 45s 失败。

### 3. 中文 + 复杂题更容易触发失败
- 英文指令「analyze the pet water fountain market opportunity」→ 25.7s 成功（content 2025 字）
- 中文「分析宠物饮水机市场机会」→ 直连有时 20s 成功、经后端 24s 失败（仍返回占位文）
- curl `-d` 发中文会被转义成 `\uXXXX`（Content-Length 36 而非 47），但 **node fetch（前端真实姿势）发的是正确 UTF-8**，所以不是前端编码问题——是 Gateway 侧偶发不产出。

## 已做的修复（bridge.js，已 git 未提交）
1. `reasoning_effort: 'low'` —— 降推理强度
2. `tool_choice: 'none'` —— 禁止 agent 调 web_search/web_fetch（之前会去抓网页拖到 168s）
3. system prompt 加「不要调用搜索/网页抓取工具」
4. fetch 加 60s `AbortSignal` 超时（之前 undici 默认 headers timeout 才触发，前端干等）
5. 识别占位文 `⚠️ Agent couldn't generate...` 转成错误，前端能降级提示而非干等
6. `Content-Type: application/json; charset=utf-8`

**效果**：从 105s 超时 → 现在 20-37s 能出结果（成功时），但**仍有偶发失败**（约占 30-50%），失败时 24-56s 后返回错误。
