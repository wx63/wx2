## 任务 3：修复报告 ID 竞态（S3）

- **背景**：检测报告 S3——`db.js addReport` 用外部生成 ID（`COUNT(*) + 1` 拼 `R-xxx`），页面 + 飞书并发创建报告时算出相同 seq → 主键冲突 500
- **位置**：`server/db.js` → `addReport()`（id 生成逻辑 + INSERT）
- **要求**（三选一，选改动最小且并发安全的）：
  - A. 事务内安全取号：`BEGIN IMMEDIATE` + `SELECT MAX` + INSERT 同事务，冲突则重试 1 次
  - B. 唯一随机后缀：`R-<时间戳>-<随机4位>`，从根上消除并发碰撞（推荐，无需迁移）
  - C. 迁移为 `INTEGER PRIMARY KEY AUTOINCREMENT`（需处理现有 `R-xxx` 数据，成本高，不推荐）
- **注意**：`reports` 表 id 目前是 TEXT 主键，`approvals.run_id` 等外键引用不变；改动后前端按 id 展示/引用的逻辑不受影响（id 仍是字符串）
- **验收**：测试中 `Promise.all` 并发调用 `addReport` 10 次，全部成功且 id 唯一（新增用例）；现有测试不回归
