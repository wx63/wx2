## 缺陷 1（🔴 P1）订单 ID 复用导致静默覆盖既有订单（数据丢失）

### 位置
`server/db.js` → `addOrder()`，约 967-971 行。

### 现状代码（节选）
```js
function addOrder(data) {
  const seq = Number(db.prepare('SELECT COUNT(*) AS n FROM orders').get().n) + 1;
  const id = 'ORD-' + String(seq).padStart(5, '0');
  const orderNo = String(data.orderNo || id);
  db.prepare(`INSERT OR REPLACE INTO orders (id, order_no, ...) VALUES (...)`)...
```

### 缺陷
1. ID 用「现存行数 + 1」生成，**删除订单后序号回退**；
2. 新订单用 `INSERT OR REPLACE`，同 ID 直接覆盖旧行。

### 复现
1. 建订单 A（`ORD-00001`）
2. 建订单 B（`ORD-00002`）
3. 删除订单 A
4. 再建订单 C → 返回 201，`id=ORD-00002`，**订单 B 被整行覆盖，无任何报错**

### 修复方案（推荐）
新建独立序列表，原子递增，新订单用普通 `INSERT`：
```sql
CREATE TABLE IF NOT EXISTS id_seq (
  name TEXT PRIMARY KEY,
  seq  INTEGER NOT NULL DEFAULT 0
);
```
```js
function nextOrderSeq() {
  db.prepare(`INSERT INTO id_seq (name, seq) VALUES ('order', 0)
              ON CONFLICT(name) DO UPDATE SET seq = seq + 1`).run();
  return db.prepare(`SELECT seq FROM id_seq WHERE name = 'order'`).get().seq;
}

function addOrder(data) {
  const seq = nextOrderSeq();
  const id = 'ORD-' + String(seq).padStart(5, '0');
  const orderNo = String(data.orderNo || id);
  // 将 INSERT OR REPLACE 改为普通 INSERT（ID 冲突时抛错，勿静默覆盖）
  db.prepare(`INSERT INTO orders (id, order_no, ...) VALUES (...)`)...
}
```
若已有线上 `orders` 数据，需把 `id_seq.seq` 初始化为现存最大订单序号（迁移脚本）。

## 缺陷 2（🟠 P2）viewer 角色可读取全部订单（越权）

### 位置
`server/index.js`：`GET /api/orders`（894 行）、`GET /api/orders/stats`（902 行）。

### 现状代码
```js
app.get('/api/orders', requireAuth, (req, res) => { ... });
app.get('/api/orders/stats', requireAuth, (req, res) => { ... });
```

### 缺陷
仅挂 `requireAuth`，未挂 `requireRole('operator','admin')`。viewer 可读全量订单明细与统计（其余 leads/approvals/agent-runs/commands 均已正确拦截，此处遗漏）。

### 修复方案
```js
app.get('/api/orders', requireRole('operator', 'admin'), (req, res) => { ... });
app.get('/api/orders/stats', requireRole('operator', 'admin'), (req, res) => { ... });
```

## 缺陷 3（🟠 P2）全局错误处理把客户端错误压成 HTTP 500

### 位置
`server/index.js` → 错误处理中间件，约 1248-1252 行。

### 现状代码
```js
app.use((err, req, res, next) => {
  if (err && err.message === 'CORS origin denied') return res.status(403).json({ ok: false, error: 'CORS origin denied' });
  console.error('[server] error:', err);
  res.status(500).json({ ok: false, error: '内部错误' });
});
```

### 缺陷
所有非 CORS 错误一律 500。实测：
- 畸形 JSON（body-parser `entity.parse.failed`，自带 `statusCode=400`）→ 返回 **500**
- 超 2MB JSON body（`entity.too.large`，自带 `status=413`）→ 返回 **500**

### 修复方案
按 `err.status`/`err.statusCode` 分流，5xx 才记日志：
```js
app.use((err, req, res, next) => {
  if (err && err.message === 'CORS origin denied') return res.status(403).json({ ok: false, error: 'CORS origin denied' });
  const status = err.status || err.statusCode || 500;
  if (status >= 500) console.error('[server] error:', err);
  const msg = status >= 500 ? '内部错误'
    : err.type === 'entity.parse.failed' ? '请求体 JSON 格式错误'
    : err.type === 'entity.too.large' ? '请求体过大'
    : '请求无效';
  res.status(status).json({ ok: false, error: msg });
});
```

## 缺陷 4（🟢 P3）订单状态字段无枚举校验

### 位置
- `server/db.js` → `addOrder()`（983 行 `status:`）、`updateOrder()`（1009 行 `status:`）
- `server/index.js` → `PATCH /api/orders/:id`（919 行，无 try/catch）

### 现状代码
```js
// db.js
status: data.status ? String(data.status).slice(0, 20) : 'pending',
// updateOrder 同
// index.js PATCH
app.patch('/api/orders/:id', requireRole('operator', 'admin'), (req, res) => {
  const order = updateOrder(req.params.id, req.body || {});
  ...
```

### 缺陷
`status` 接受任意 ≤20 字符字符串（实测 `not_a_status` → 201）。`orderStats()`（db.js:1023-1028）只统计 `pending`/`shipped`，非法状态计入 total 但不进任何桶 → 统计口径失真。

### 修复方案
1. 定义白名单常量（按业务实际状态机调整）：
```js
const ORDER_STATUSES = ['pending', 'paid', 'shipped', 'delivered', 'cancelled'];
```
2. 在**路由层**校验并返回 400（不要只靠 db 层 throw，PATCH 路由无 try/catch 会把异常抛给全局错误处理变成 500）：
```js
app.post('/api/orders', requireRole('operator', 'admin'), (req, res) => {
  const data = req.body || {};
  if (!data.orderNo) return res.status(400).json({ ok: false, error: '缺少 orderNo' });
  if (data.status !== undefined && data.status !== null && data.status !== '' && !ORDER_STATUSES.includes(data.status))
    return res.status(400).json({ ok: false, error: '非法订单状态' });
  ...
});
// PATCH 同样在校验后调用 updateOrder
```
