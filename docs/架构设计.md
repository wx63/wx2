# OpenClaw 跨境电商智能体 — 系统架构 v1.0

> 基于 OpenClaw 构建的跨境电商运营矩阵（MVP 优先，渐进演进）
> 日期：2026-07-31 · 作者：小吴（OpenClaw 架构设计）

---

## 一、设计原则

1. **MVP 先行**：先跑通 1 个完整业务闭环，再横向扩展 agent 数量
2. **按需实例化**：专业 agent 用 subagent（子任务）按需拉起，不长期常驻 5 个 agent（省 token、免记忆污染）
3. **记忆分层**：全局知识（运营规范）放共享 memory，业务数据放各 agent 自己的 workspace
4. **模型按场景选**：长上下文任务用 glm-5.2（40万），轻量任务用 kimi/qwen flash（快、便宜）
5. **一切可审计**：所有对外动作（发帖、发消息、上架）默认人工确认，AI 只做"建议 + 草稿"

## 二、总体架构（四层）

```
┌─────────────────────────────────────────────────────────┐
│  L1 接入层（入口）                                       │
│  飞书群 / 微信 / WebChat / 邮件 / Webhook(n8n等)         │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  L2 编排层（大脑）                                       │
│  Main Agent「运营总监」                                  │
│  · 意图识别：判断任务类型                                │
│  · 任务路由：分派给专业 agent / skill                    │
│  · 审批闸门：对外动作先出方案，人工确认后执行             │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  L3 能力层（按需拉起）                                   │
│  ├─ Subagent A: 市场调研员（VOC/竞品/趋势）              │
│  ├─ Subagent B: 内容创作员（Listing/SEO/多语种/脚本）    │
│  ├─ Subagent C: 客服专员（RAG知识库 + 工单）             │
│  ├─ Subagent D: 风控审查员（侵权词/敏感词/水印检测）     │
│  └─ Skills 工具箱（每个技能 = 一个 SKILL.md）            │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  L4 数据层                                               │
│  · memory/（agent 记忆 + 运营知识沉淀）                  │
│  · 知识库/（RAG 文档：尺码表、政策、产品手册）           │
│  · data/（线索表、订单表、竞品快照 —— CSV/JSON/SQLite） │
│  · config（平台账号凭据，环境变量管理）                  │
└─────────────────────────────────────────────────────────┘
```

## 三、Agent 职责矩阵

### 常驻：Main Agent「运营总监」(agentId: main)
| 职责 | 说明 |
|---|---|
| 统一入口 | 所有渠道消息汇聚于此，识别意图 |
| 任务路由 | 调用 subagent 处理专业任务，或直接执行轻量任务 |
| 审批闸门 | 对外动作（发帖/回复/下单）先产出方案，等人工确认 |
| 知识沉淀 | 把踩坑记录、操作规范写入 AGENTS.md / memory |
| 定时任务 | 通过 cron 驱动日报、监控、周报 |

### 按需拉起：Subagents（sessions_spawn 创建）
| Subagent | 触发场景 | 主要工具 | 输出物 |
|---|---|---|---|
| 市场调研员 | "调研XX品类""分析竞品" | web_search, web_fetch | 调研报告.md |
| 内容创作员 | "写Listing""做SEO标题" | 写作 + 校验 | 多语种文案草稿 |
| 客服专员 | 客户咨询、查单 | 知识库检索 + 工具调用 | 回复草稿/工单 |
| 风控审查员 | 上架前审核 | 规则库 + 图片分析 | 违规点清单 |

> 说明：subagent 用完即销毁，不占常驻上下文；这是 OpenClaw `sessions_spawn` 的天然优势。

## 四、Skills 工具箱（按 MVP 优先级排序）

### P0 — 第一阶段（先跑通闭环）
| Skill | 功能 | 依赖 |
|---|---|---|

| `listing-writer` | 多语种 Listing + SEO 标题生成 | 模板 + LLM |
| `compliance-check` | 敏感词/禁用表述/水印检测 | 规则库 |

### P1 — 第二阶段（提效）
| Skill | 功能 |
|---|---|
| `market-research` | 竞品采集 + 趋势分析 |
| `social-scheduler` | 社媒内容排期（合规频率，非矩阵） |
| `report-weekly` | 每周运营数据汇总周报 |

### P2 — 第三阶段（进阶，谨慎）
| Skill | 功能 | 注意 |
|---|---|---|
| `erp-connector` | ERP 查单/库存（Function Calling） | 只读为主 |

| `auto-listing` | 平台自动上架 | 强烈建议走官方 API，不爬后台 |

## 五、数据与知识管理

```
workspace/  (Main Agent 或独立跨境电商工作区)
├── AGENTS.md          # 运营规范、命令约定
├── memory/            # 日常记忆（踩坑记录、决策日志）
├── MEMORY.md          # 长期记忆（浓缩知识）
├── 知识库/            # RAG 源文档（只读）
│   ├── 尺码对照表.md
│   ├── 退换货政策.md
│   └── 产品手册/
├── data/              # 业务数据（结构化）
│   ├── leads.csv      # 线索表（分级打标后）
│   ├── orders/        # 订单快照
│   └── competitors/   # 竞品调研快照
└── skills/            # 自定义技能
    ├── kb-query/SKILL.md
    ├── lead-scoring/SKILL.md
    └── ...
```

**记忆防污染规则**：
- 业务数据（线索/订单）只写 data/，不写 memory/
- 踩坑教训写 memory/YYYY-MM-DD.md，每周五提炼进 MEMORY.md
- 过时数据（旧竞品快照）定期归档到 data/archive/

## 六、自动化调度（cron）

| 任务 | 频率 | 动作 |
|---|---|---|
| 线索日报 | 每日 09:00 | 汇总昨日新线索+分级，推送飞书 |
| 订单异常监控 | 每 2h | 检查未发货/超时订单，异常告警 |
| ROAS 周报 | 每周一 10:00 | 汇总广告数据，异常时预警（不自动操作） |
| 知识沉淀 | 每周五 17:00 | 从 memory/ 提炼周报，更新 MEMORY.md |
| 竞品快照 | 每周三 | 采集主要竞品价格/评价快照 |

## 七、部署建议

- 就在你这台 Windows 机器上跑（OpenClaw 已装好）
- 注意：本地电脑关机 = 系统离线，适合开发测试

- 7x24 在线，飞书/微信通道常驻
- 数据卷挂载，备份 memory/ + data/ + 知识库/

## 八、MVP 落地路线图

### Phase 1（第 1 周）：跑通"客服闭环"
1. 建 `知识库/`，放 2-3 份真实文档（尺码表、退换货政策）
2. 写 `kb-query` skill
3. 微信通道测试：客户问"这件衣服有 XL 吗" → AI 查知识库 → 给出带尺码对照的答复草稿
4. 验收标准：10 个真实问题，8 个以上答案正确且引用文档

### Phase 2（第 2 周）：加"线索打标"
1. 写 `lead-scoring` skill
2. 接 WhatsApp/飞书进线，自动识别"提到规格/MOQ"的客户
3. 产出 leads.csv + 每日 09:00 线索日报（cron）
4. 验收：能区分【高意向-B端】/【普通】/【垃圾】

### Phase 3（第 3-4 周）：内容 + 合规
1. `listing-writer`：批量生成多语种 Listing 草稿
2. `compliance-check`：上架前自动扫描违规点
3. 每周知识沉淀周报上线

### Phase 4（第 5 周起）：按需扩展
- 市场调研、社媒排期、ERP 连接……
- 每加一个能力 = 写一个 skill + 一个验收用例

## 九、明确不做（防跑偏）

1. ❌ 不做"防关联矩阵发帖"（灰产风险，违反平台 TOS）
2. ❌ 不做浏览器爬平台后台自动上架（走官方 API）
3. ❌ 不让 AI 自动下单/自动发广告（只建议，人工确认）
4. ❌ 不一次常驻 5 个 agent（成本高、记忆互相污染）

## 十、技术备注（OpenClaw 机制对照）

| 需求 | OpenClaw 机制 |
|---|---|
| 多角色分工 | `agents.list` 多 agent + `sessions_spawn` 子任务 |
| 技能扩展 | `<workspace>/skills/<name>/SKILL.md` |
| 定时任务 | cron（isolated agentTurn / systemEvent） |
| 知识记忆 | memory/ + MEMORY.md + 记忆检索 |
| 外部集成 | webhook、browser 插件、MCP 服务器 |
| 渠道接入 | 飞书/微信/Telegram/WhatsApp 通道 + bindings |
| 长任务编排 | TaskFlow（flow + 子任务，重启不丢状态） |
