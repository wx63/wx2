# 多轮指令上下文（会话记忆）— 执行方案（Codex）

> 依据：用户反馈"只能接受单一指令，基于上一指令结果继续下一步时没有后续"。
> 根因：系统为单指令模式，每次指令的 prompt 只含当前指令 + 知识库，从不带上一次指令的结果。

## 现状（代码位置）

- `server/index.js:321`（`runAgenticCommand` 内）prompt 构造：
  ```js
  const prompt = `${command}\n\n${kbContext ? '知识库上下文：\n' + kbContext + '\n\n' : ''}${priceHint}`.trim();
  ```
  只含当前 `command`，无历史。
- `server/db.js` `commands` 表已存全部历史：`id, user_id, command, agent_id, session_id, status, content, ...`
- `session_id` 目前仅透传给模型 API（`bridge.js:203`），**未**用于拉取历史
- 飞书渠道已有会话隔离：`index.js:633` `sessionId: "feishu:" + chatId`

## 改动

### 1. `server/db.js` — 新增历史查询函数

```js
// 取某用户/会话最近 N 条已完成指令（command + 结果摘要），用于拼多轮上下文
// excludeId: 排除当前这条指令（历史里不含本条）
function listRecentCommands({ userId, sessionId, limit = 5, excludeId } = {}) {
  const clauses = [];
  const params = {};
  if (userId != null) { clauses.push('user_id = @userId'); params.userId = userId; }
  if (sessionId) { clauses.push('session_id = @sessionId'); params.sessionId = sessionId; }
  if (excludeId != null) { clauses.push('id != @excludeId'); params.excludeId = excludeId; }
  clauses.push("status = 'ok'");
  clauses.push("content IS NOT NULL AND content != ''");
  const where = clauses.length ? ' WHERE ' + clauses.join(' AND ') : '';
  return db.prepare(
    `SELECT id, command, content FROM commands ${where} ORDER BY id DESC LIMIT @limit`
  ).all({ ...params, limit });
}
```

> 注意：`commands` 表还有 status='queued' 的待审批指令（`db.js:559`），查询只取 `status='ok'` 已完成且有结果的。若确认该表还有其它完成态（如 'done'），按实际枚举调整。

### 2. `server/index.js` — prompt 注入历史

在 `runAgenticCommand` 内新增辅助函数并在 prompt 构造处拼接：

```js
// 构造多轮对话历史文本（放 runAgenticCommand 之前或模块级）
function buildConversationHistory(meta) {
  try {
    const { listRecentCommands } = require('./db');
    const recent = listRecentCommands({
      userId: meta.userId,
      sessionId: meta.sessionId,
      limit: 5,
      excludeId: meta.commandId,
    });
    if (!recent.length) return '';
    const lines = recent.reverse().map((c, i) => {
      const content = String(c.content || '').slice(0, 400); // 每条约 400 字，控 token
      return `[${i + 1}] 用户：${String(c.command).slice(0, 200)}\n    助手：${content}`;
    });
    return '对话历史（来自之前的指令）：\n' + lines.join('\n\n');
  } catch (e) {
    console.warn('[history] build failed:', e.message);
    return '';
  }
}
```

prompt 构造改为：

```js
const history = buildConversationHistory(meta);
const prompt = `${history ? history + '\n\n' : ''}${command}\n\n${kbContext ? '知识库上下文：\n' + kbContext + '\n\n' : ''}${priceHint}`.trim();
```

要点：
- `meta.userId` / `meta.sessionId` / `meta.commandId` 均为现有字段（`executeAgentCommand` 已传入）
- 历史构建失败**静默降级**（不阻断主流程）
- 只改 `runAgenticCommand` 主路径；`runPlannedStep` fallback 路径不改（步骤执行不需要历史）

### 3. 前端 — 不改（可选）

- 网页端如未传 `session_id`，历史按 `user_id` 聚合即可；飞书已按 `feishu:chatId` 隔离
- 如需"新会话"按钮（清空上下文），留待后续，本期不做

## 边界与规则

1. 历史最多 5 条、每条 command ≤200 字、content ≤400 字（总注入 ≈ 3000 字，token 成本可忽略）
2. 只取 `status='ok'` 且 content 非空的指令
3. 排除当前指令本身（`excludeId`）
4. 按 `userId` + `sessionId` 过滤（网页用户互不串、飞书群互不串）
5. 历史构建失败不影响主流程

- 风险：低。只读查询 + prompt 文本拼接；失败静默降级
- 回滚：还原 `index.js` prompt 构造处即可（`db.js` 新增函数可保留，无副作用）
- 不碰：`.env`、`data/`、审批/订单/知识库逻辑、前端
