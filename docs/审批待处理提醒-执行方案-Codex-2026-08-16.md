# 审批待处理提醒 — 执行方案（Codex）

> 目标：有审批单待处理时，定时通过飞书 + 邮件通知运营者，无需守着页面刷新。
> 本方案只新增"扫描 + 通知"能力，不修改审批业务逻辑。

## 背景与现状

- 系统：跨境电商智能体（Express + Node 22 + SQLite），部署于 http://106.55.18.244:3001
- `approvals` 表已有字段：id, title, command, action, draft, status('pending'|'approved'|'rejected'), risk, created_by, created_at, decided_at, executed_at, execute_status 等
- `server/scheduler.js` 已有日调度器框架（digest / backup 两个任务点），复用其启动方式
- `server/feishu.js` 已导出 `sendText(chatId, text)`（长连接已配，可直接发）
- `server/executors/email.js` 已上线（SMTP 已配置，`execute(approval)` 可真实发信；`action:'notify'` 在其 matches 范围内）

## 改动文件

### 1. `server/db.js` — 表结构 + 查询函数

**a) approvals 表新增列 `notified_at`（幂等迁移）**

在数据库初始化处（CREATE TABLE 之后），加一段兼容迁移：

```js
// 幂等：检查列是否存在，不存在则 ADD COLUMN
const cols = db.prepare("PRAGMA table_info(approvals)").all();
if (!cols.some(c => c.name === 'notified_at')) {
  db.exec("ALTER TABLE approvals ADD COLUMN notified_at TEXT");
}
```

**b) 新增查询函数**

```js
// 待提醒的审批单：pending 且从未提醒过
function listPendingApprovalsUnnotified(limit = 20) {
  return db.prepare(
    "SELECT * FROM approvals WHERE status = 'pending' AND (notified_at IS NULL OR notified_at = '') ORDER BY created_at ASC LIMIT ?"
  ).all(limit);
}

// 标记已提醒
function markApprovalNotified(id, notifiedAt) {
  return db.prepare("UPDATE approvals SET notified_at = ? WHERE id = ?").run(notifiedAt, id);
}
```

导出这两个函数（沿用现有 db.js 的导出风格）。

### 2. `server/scheduler.js` — 周期扫描任务

在 `startScheduler()` 内新增一个独立的 `setInterval`（不要塞进每日 targetMinutes 框架）：

```js
// 审批提醒扫描（周期任务）
const reminderEnabled = process.env.APPROVAL_REMINDER_ENABLED !== 'false';
const reminderInterval = Math.max(60 * 1000, Number(process.env.APPROVAL_REMINDER_INTERVAL_MS) || 5 * 60 * 1000);
let reminderTimer = null;

function startReminderLoop() {
  if (!reminderEnabled) return;
  reminderTimer = setInterval(runApprovalReminder, reminderInterval);
  reminderTimer.unref && reminderTimer.unref();
  // 启动后 30 秒先跑一次，不用等满一个周期
  setTimeout(() => runApprovalReminder().catch(() => {}), 30 * 1000).unref?.();
}

async function runApprovalReminder() {
  const { listPendingApprovalsUnnotified, markApprovalNotified } = require('./db');
  const pending = listPendingApprovalsUnnotified(20);
  if (!pending.length) return;

  const alertChatId = process.env.FEISHU_ALERT_CHAT_ID || '';
  const nowIso = new Date().toISOString();
  let notified = 0, failed = 0;

  for (const ap of pending) {
    const text = [
      `【审批提醒】${ap.title || '未命名审批'}`,
      `单号: ${ap.id}`,
      `动作: ${ap.action || '-'}`,
      `提交时间: ${ap.created_at || '-'}`,
      '请到控制台处理：http://106.55.18.244:3001',
    ].join('\n');

    // 飞书
    if (alertChatId) {
      try { await feishu.sendText(alertChatId, text); } catch (e) { failed++; console.error('[reminder] feishu fail:', e.message); }
    }
    // 邮件（复用 email 执行器）
    try {
      const { executeApproval } = require('./executors');
      const r = await executeApproval({ id: ap.id, action: 'notify', title: `审批待处理：${ap.title}`, content: text });
      if (!r.executed) { failed++; console.error('[reminder] email fail:', r.reason); }
    } catch (e) { failed++; console.error('[reminder] email err:', e.message); }

    // 任一渠道成功即标记已提醒（飞书未配置时只看邮件；两边都失败则下轮重试）
    if (failed === 0 || (alertChatId && notified > 0)) {
      // 简化策略：飞书配置了且发送成功，或邮件成功，都算提醒成功
    }
    notified++;
  }

  // 简单可靠策略：逐条判断，成功（飞书成功 或 邮件成功）就标记
  // 上面循环内按此逻辑实现；此处仅示意
  console.log(`[reminder] scanned ${pending.length}, notified ${notified}, failed ${failed}`);
}
```

> 实现提示：上面伪代码中"简化策略"一段，请按下面明确规则实现——
> **每条审批单**：飞书发送成功 或 邮件发送成功，即 `markApprovalNotified(id, nowIso)`；两者都失败则不标记（下轮自动重试）。注意 `failed` 计数要按"该条是否两个渠道都失败"来判断，不要跨条累计。

在 `stop()` 中增加 `reminderTimer && clearInterval(reminderTimer)`。

## 边界与规则

1. 同一单只提醒一次：`notified_at` 非空即跳过
2. 已处理单（approved/rejected）自然不在扫描范围
3. 存量 pending 单首次扫描会全部提醒一遍（可接受，属预期）
4. 单次最多扫 20 条，避免轰炸；下轮继续
5. 两个渠道都失败 → 不标记 → 下轮重试
6. 不修改审批创建/审批处理逻辑，不动 `data/`，不动 `.env` 其他键

## 验收标准

- [ ] 提交一个审批单 → 1 个扫描周期内（默认 5 分钟，可临时调小验证）收到飞书提醒 或 邮件提醒
- [ ] 同一单第二次扫描不再提醒
- [ ] 审批处理后不再收到提醒
- [ ] 飞书未配置时，邮件正常发出且不报错
- [ ] `npm test` 44/44 全绿
- [ ] 服务重启后提醒功能自动恢复（setInterval 随 startScheduler 启动）
