## 2. 测试方法

1. **不污染真实环境**：所有测试使用 `NODE_ENV=test`，通过 `OPENCLAW_DB_PATH / OPENCLAW_DATA_DIR / OPENCLAW_KB_DIR` 指向一次性临时目录（`os.tmpdir()` 下自动创建、结束后删除）。真实 `data/app.db`、`.env`、`知识库/` 全程只读，运行前/后内容一致。
2. **零真实成本**：模型调用使用 127.0.0.1 回环 mock 服务，按协议返回 `tool_calls` / 最终文案，不产生任何真实 LLM 费用。
3. **三层覆盖**：
   - **集成层**（`api.test.js` / `coverage.test.js`）：直接 require 应用与数据库，覆盖 DB 逻辑与 HTTP 路由。
   - **前端层**（`frontend.*.test.js`）：jsdom 加载 `public/` 真实页面脚本，模拟点击/输入/提交，断言 DOM 与请求。
   - **端到端层**（`e2e-live.test.js`）：启动独立 Express 实例（127.0.0.1:3121）走真实 HTTP + 会话 Cookie，用 mock 模型走完整指令→工具调用→审批/报告链路。

## 6. 发现的问题

### 6.1 【影响轻微】"取消进行中运行"是表面取消（状态回写覆盖）

- **现象**：对运行中的 agentic 任务点"取消"，接口立即返回 `status: 'cancelled'`；但底层模型调用并未终止，调用返回后 `finishAgentRun` 无条件把状态覆盖回 `ok`，任务最终仍"完成"且步骤照常记录。
- **证据**：e2e 用 mock 挂起模型响应 → 取消 → `cancelled`；释放响应后 1500ms 复读 → `ok`（临时探针脚本实测确认，探针已删除）。
- **影响**：不影响数据安全，任务结果仍正确入库；仅 UI 状态与用户预期不一致（可能显示"已取消"而后又变为完成）。
- **建议**（后续）:在 `finishAgentRun` 中若当前状态已是 `cancelled` 则不覆盖，或取消时向进程注入终止信号。**当前版本可不修，不影响正常使用。**

### 6.2 【设计说明，非缺陷】`/api/health` 需登录

`routes/index.js` 在 health 之前挂载了全局 `requireAuth`，因此健康检查也需会话。若未来需对监控/负载均衡暴露公开健康端点，可把 health 路由移到认证中间件之前。

### 6.3 【测试隔离说明】KB 上传/删除回环短暂触及真实 `知识库/` 目录

`routes/kb.js` 中上传/删除写路径硬编码到项目 `知识库/`（检索读路径支持 `OPENCLAW_KB_DIR` 隔离）。测试的上传→删除回环结束后已在 after 钩子删除残留文件，运行后该目录仍为原始 8 个文件（已复核）。此为本项目架构设计，无需修改。
